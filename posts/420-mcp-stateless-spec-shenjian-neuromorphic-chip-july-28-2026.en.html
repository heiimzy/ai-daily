MCP 2026-07-28 Final Spec: The 'De-state-ification' of AI Agent Infrastructure

Early July 28, the Model Context Protocol (MCP) maintainers formally published the 2026-07-28 specification — the largest architectural revision since the protocol's November 2024 launch. Industry outlets are calling it "the most consequential update in the protocol's history." MCP, the open standard connecting AI agents to external tools, data sources, and APIs, was introduced by Anthropic in November 2024 and has since been adopted by OpenAI, Google DeepMind, Microsoft, AWS, and hundreds of enterprise software vendors, now governed by the Linux Foundation's AI Agent Foundation.

The headline change: MCP is now stateless at the protocol layer. In previous versions, every MCP connection opened with an initialize handshake and received an Mcp-Session-Id header, pinning each client to whichever server instance issued it. This forced sticky load balancer routing and shared Redis session stores for any horizontally scaled deployment — a significant operational tax.

Three Core Changes in Detail

1. initialize/initialized Handshake and Mcp-Session-Id Removed

Two Specification Enhancement Proposals (SEP-2575 and SEP-2567) eliminate the initialize handshake and the Mcp-Session-Id header entirely. Protocol version, client info, and capabilities that used to be exchanged once at connection time now travel in the _meta field on every individual request. A new server/discover method lets clients query server capabilities on demand. The result: any MCP request can land on any server instance — no sticky routing, no shared session store required.

"This is the most substantial change we have made to the specification, probably since adding authorization. A lot of things that made MCP are gone." — David Soria Parra, MCP core maintainer, during the July 23 livestream

2. New Required Headers: Mcp-Method and Mcp-Name

The new spec requires Mcp-Method and Mcp-Name headers on every request (SEP-2243). Load balancers, gateways, and rate-limiters can now route or throttle based on operation without parsing the JSON-RPC body. Servers reject requests where headers and body disagree — preventing routing confusion.

3. Tasks Graduated to Extension, Three Features Deprecated

The Tasks primitive for long-running work moves from experimental core feature to a formal extension, rebuilt around statelessness: tools/call now returns a task handle, and clients drive progress with tasks/get, tasks/update, and tasks/cancel. Notably, tasks/list was removed — a stateless server has no session-scoped list to enumerate. Additionally, Roots, Sampling, and Logging enter a formal 12-month deprecation pipeline.

GitHub announced on July 23 that its GitHub MCP Server would ship updated support for the new spec, removing Redis session storage and deep packet inspection. Microsoft's Azure App Service team published migration guidance, stating "hosting a horizontally scaled MCP server is now as simple as deploying a normal web app."

Shenjian Technology Unveils 'Bosuo' Neuromorphic Chip: 100x Energy Efficiency Through 3D Compute-in-Memory

In a concurrent development early July 28 at the Global Semiconductor Innovation Summit in Shenzhen, Shenjian Technology officially launched 'Bosuo' (博索), a neuromorphic computing chip developed over three years. The chip features a revolutionary 3D compute-in-memory architecture delivering 10 TOPS/W — over 100x better energy efficiency than traditional GPUs — marking a new era for edge AI computing.

Technical Breakthrough: 3D Compute-in-Memory + Memristor Array

Bosuo's core innovation is the tight integration of storage and computation in three-dimensional space. The bottom layer uses an HfO₂-based memristor array where each cell stores 1-bit of weight while simultaneously performing multiply-accumulate operations. The middle layer connects to the top digital control unit through nano-scale through-silicon vias, enabling 1,024 parallel compute columns. Non-volatile memristors ensure weights survive power loss — achieving true zero static power storage.

In benchmark testing against the NVIDIA Jetson TX2 (16nm), Bosuo (22nm) delivered: 22ms inference latency at 180mW for ResNet-50 image classification (9.8 TOPS/W vs 0.6 TOPS/W — 16.3x improvement), and an astonishing 45μW for voice wake-up tasks — over two orders of magnitude better energy efficiency.

Go-to-Market: From Wearables to Industrial IoT

Bosuo measures just 4mm², uses mature 22nm FD-SOI process from SMIC, and has achieved over 90% yield in early runs. Shenjian has partnered with two domestic packaging and testing firms, planning small-batch production in Q4 2026 with initial capacity of 150,000 units per month at under $2 per chip.

Six application scenarios are already in prototype validation: smart wearables (0.3mW power consumption, 30-day battery life), smart home sensors, industrial predictive maintenance, autonomous driving roadside units, portable medical diagnostics, and acoustic event detection. As Shenjian's CEO stated: "Bosuo's mass production doesn't require advanced process nodes — significantly reducing supply chain risk. It brings computing back to its ultimate form: ubiquitous yet imperceptible."
